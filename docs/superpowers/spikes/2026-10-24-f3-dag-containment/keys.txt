F3 question 2 -- what happens to F1's scalar containment key

F1's key: "one scalar column per row holding the id of the row's ancestor
at a declared containment depth". Five candidates, one table, 10,000,000 rows.

  K1 ep_zone      scalar, declared on the tree dimension: the fact's episode
  K2 zones[]      every direct container, GIN
  K3 zones3[]     the same lifted to entity-set level 3
  K4 per-kind     ep_zone scalar + set_zones[] GIN, one key per containment kind
  K5 canonical    one designated primary container per fact, scalar

=== K1 in a DAG: the key set cannot be read off the container graph =========
No episode is a descendant of an entity-set, so a principal whose grant is on
an entity-set has an EMPTY episode key set while holding authorized facts. The
only sound construction walks the authorized facts. Its cost:
