# iam use-case corpus — status ledger.
#
# Regenerate with: go test ./examples/... -run TestLedger -update-ledger
#
# live           every assertion runs against the real module today: the
#                identity fixture, the grants, and the expectation table,
#                which is answered by iam.Decide and the corpus's reference
#                oracle and diffed between them (design §9.4).
# pending        the scenario waits on the named `iam` capability. Everything
#                it can run still runs, and most pending tables are now
#                answered by both evaluators too — what is missing is the
#                half of the scenario's claim about the design that no code
#                here can carry yet.
# unexpressible  the design cannot express the use case; the named §17
#                finding is where it bites. See UNEXPRESSIBLE.md.
#
# A pending row that stays pending after its capability lands is the
# failure mode this corpus exists to avoid, so two things watch it: the
# api.txt tripwire in scenario/pending.go, which fails automatically, and
# this file, which makes every change to the set a reviewed diff.
